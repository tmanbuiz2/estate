# Delivery roadmap

## Implemented in the first commit

- [x] Responsive web discovery, local home illustrations and explicit demonstration labels.
- [x] Monthly cost breakdown, budget and bedroom filters, accessibility/pet filters.
- [x] Save, compare, local viewing/application drafts and repair notebook.
- [x] Read-only Worker routes, explicit errors and safe public projections.
- [x] Draft-first D1 listing schema and effective-date rule register schema.
- [x] Automated domain and API tests; CI checks/build artifact.
- [x] Shared-domain Expo mobile client scaffold.

## Next: private pilot infrastructure

- [ ] Agree the business role with NB counsel/FCNB: publisher, software provider, broker or property manager. Rental trading definitions are broad; do not assume a listing platform is exempt.
- [ ] Choose production branding and review trademark/domain availability.
- [ ] Implement verified accounts, recovery, MFA for administration, server authorization, request throttling and abuse controls.
- [ ] Add landlord listing drafts, evidence checks, human moderation and reconfirmation expiry.
- [ ] Connect the web client to reviewed live inventory; add cursor pagination and unknown-cost UI states.
- [ ] Implement viewing requests with real landlord availability and explicit acknowledgement.
- [ ] Add monitored report/block/appeal workflows.
- [ ] Agree privacy purposes, retention, processor contracts, hosting disclosures and complaint handling.
- [ ] Complete French UI/content and accessibility testing with assistive technology.
- [ ] Run real browser/device QA, mobile build/export checks, D1 integration checks and security review.

## Then: applications and tenancy operations

- [ ] Consent-based reusable applications and alternative evidence for newcomers.
- [ ] Private document handling only after retention/deletion/access controls and provider review.
- [ ] Applicant status tracking with explanations and a correction/appeal route.
- [ ] NB tenancy categories and exceptions, reviewed official form mapping and effective-date rules.
- [ ] Legal notice service only through reviewed statutory delivery paths.
- [ ] Real repair requests, inspection evidence and role-based communications.

## Separate launch gates

- [ ] Credit checks: consent, NB reporting-law assessment and a reviewed screening provider.
- [ ] Payment collection/escrow/wallet: payments-law, FINTRAC, deposit-routing and provider assessment. A vendor integration does not automatically exempt the platform.
- [ ] Paid subscriptions: applicable consumer law commencement, all-in pricing, renewals/cancellation/refunds, tax and store billing assessment.
- [ ] Canada-wide listings: province/territory and municipal requirements matrix, including Quebec language/privacy obligations where applicable.
- [ ] Store release: privacy/data-safety disclosures, deletion flows, UGC moderation, account/demo access and billing review.

No APK, IPA, TestFlight upload or production deployment is delivered by the first source commit. Creating those requires the corresponding build/hosting setup and release gates.
